# WP-A: `GameEngine` decomposition (PR 2 of #1559)

Scope: `app/core/game_engine.cpp`, `game_engine.h`, `game_engine_composition.cpp`, and the collaborators extracted from them. Behaviour is unchanged: same tick phase order, same `FrameBarrier` protocol, same QML surface (35 `Q_PROPERTY` and 8 `Q_INVOKABLE` lines, as `qml_surface_test` counts them, and identical signals).

The engine keeps: the Qt facade (properties, invokables, signals), the three frame entry points (`simulate`, `update_presentation`, `render`), match load/save/load-game sequencing, and the composition root. It no longer keeps the internal state of any feature listed below.

## Composition

`game_engine_composition.cpp` is now the ordered list of construction steps: `create_session`, `create_view_models`, `create_feature_runtimes`, `wire_view_models`, `create_render_services`. `game_engine_wiring.cpp` holds the per-feature `wire_*` functions: `wire_victory_service`, `wire_loading_and_saves`, `wire_world_services`, `wire_map_catalog`, `wire_audio`, `wire_production_and_placement`, `wire_command_controller`, `wire_selection_and_cursor`, `wire_event_subscriptions`. The save view-model signals are connected by `SaveSlotController::connect_view_model`, the minimap event subscriptions by `MinimapEvents` itself.

## Invariants kept (and where they are pinned)

- Tick order under one frame-mutex hold: `try_begin_simulation` -> `simulate` -> `update_presentation` -> `drain_pending_capture` -> `end_simulation` (`save_capture_coherence_test`, `simulation_lifecycle_test`).
- Mission waves and stages advance on the consumed fixed step, never on the scaled wall delta (`mission_tick_ownership_test` greps `GameEngine::simulate`, which stayed in `game_engine.cpp`).
- Save capture happens on the simulation thread under the frame lock; the GUI-thread fallback takes `lock_frame()` first (`save_capture_coherence_test` now reads `save_slot_controller.cpp` and `simulation_lifecycle.cpp`).
- Both save and load force commander mode back to RTS (`commander_control_regression_test` updated to the new locations).
- Subscription order for `UnitDiedEvent` is unchanged: the engine (entity cache, kill counter) first, the minimap after.
- Translated strings keep the `GameEngine` context: extracted code calls `QCoreApplication::translate("GameEngine", ...)`, so no `.ts` entry moves.
- Frame-lock rule for QML entry points (`scripts/check-frame-lock.py`): `get_owner_info`, `get_player_stats`, `local_player_nation` still hold the frame mutex.

## Destruction order

Members are destroyed in reverse declaration order, after `~GameEngine` has: forgotten the victory session contributor, joined the simulation thread (`SimulationLifecycle::stop`), and shut the save controller (`shutdown`: stop autosave timer, wait for pending saves, disconnect service, shut it down) and the audio services down. Anything that holds a raw pointer to a view model (`MissionRuntime`, `CommanderMessageRuntime`, `EconomyReadModel`, `SaveSlotController`, `MinimapEvents`, `OrderFeedbackPresenter`, `TargetingPresentation` inputs) is declared after the view models, so it is destroyed first. Event subscriptions are the last data members, so they unsubscribe first.

## Guard tests changed

- `tests/core/commander_control_regression_test.cpp`: `SaveAndLoadForceCommanderModeBackToRts` checks `save_slot_controller.cpp` and `game_engine_wiring.cpp` for the save half.
- `tests/core/mission_tick_ownership_test.cpp`: unchanged (the text it scans still exists).

## New tests (all `app_tests`)

`ally_announcements_test`, `simulation_lifecycle_test`, `loading_overlay_test` (about 1.2 s of real sleeping for the 1 s minimum on-screen time), `replay_coordinator_test` (records and plays back a real replay file), `battle_stats_test` (also covers `EntityCache` events and the defeat text).

## Left for follow-up

- `game_engine.h` still needs `ViewportState` (in `app/input/input_command_handler.h`) as a value member; extracting `ViewportState` is part of the input package.
- `start_skirmish_internal`/`complete_match_load` and `load_game_from_slot` are sequences over the whole engine state (runtime flags, level, world, renderer, view models). They are short now (<45 lines each) but still live in the engine; moving them further needs a context of the size the epic forbids.
- Removed as dead code: `GameEngine::update_cursor(Qt::CursorShape)`, `GameEngine::world_to_screen`, `FrameLockWaiter`. `FrameLockStats::deferred_presentations` and `forced_presentation_waits` are never written but stay because `GLView` reports them.
