# Refactoring inventory (issue #1559)

Tracked inventory for the readability epic in [#1559](https://github.com/djeada/Standard-of-Iron/issues/1559). It records every C++ file under `app/` and `game/` at or above 1,000 physical lines, what each one mixes, which existing type should own each concern, and how a change is validated. It is the PR 1 baseline: no production code moved with it.

`scripts/refactor-inventory.py --check` (run by `scripts/check-pr-policy.py`) fails when a file at or above 1,000 lines is not listed with status `exception` or `open`, when a row marked `done` grew back to 1,000 lines, or when a still-large file's recorded `after` count drifts by more than 10%.

Function extents are approximated from column-zero definitions (see the script), so "longest function" is a review signal, not a parse. Line counts include comments and blanks.

Splitting a file without splitting these functions only relocates them.

## Ownership and thread rules (reference for every extraction)

- **Simulation thread** (`QThread` "SoISimulation", `GameEngine::run_simulation_thread`): `simulate`, `update_presentation`, `drain_pending_save_capture`, `CommandQueue::drain`, world systems, presentation publication (`Published<T>`, `PresentationFrame`).
- **GUI/QML thread**: input, view models, `lock_frame()` holders, `WorldFreeze` transitions, loading orchestration, save completion callbacks.
- **Render thread** (Qt Quick scene-graph): `GLView::GLRenderer::render` -> `GameEngine::render`. It reads the atomically published `PresentationFrame` and the world render snapshot and never mutates simulation state.
- **Save worker** (`SaveLoadService::worker_loop`): owns its own `SaveStorage` connection; consumes an already-captured snapshot.
- `FrameBarrier` arbitrates freeze/render/simulation phases. Synchronization changes are separate behavioural changes and need their own evidence.
